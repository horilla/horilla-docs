# **Recruitment**

The Recruitment module takes a job from an opening, through candidates and interviews, to a hire. Open it from **Recruitment** in the sidebar.

## **Pages in this chapter**

| Page | Where | What it is for |
|---|---|---|
| [Recruitment Dashboard](/hr/functional/v2.0/recruitment/dashboard) | **Recruitment → Dashboard** | Hiring figures and charts |
| [Recruitment Pipeline](/hr/functional/v2.0/recruitment/pipeline) | **Recruitment → Recruitment Pipeline** | Candidates by stage, per recruitment |
| [Job Openings](/hr/functional/v2.0/recruitment/job-openings) | **Recruitment → Job Openings** | Create and manage recruitments |

## **How the pieces fit**

1. An administrator defines **stages** (for example *Applied, Interview, Hired*) in [Configuration](/hr/functional/v2.0/recruitment/configuration).
2. A [job opening](/hr/functional/v2.0/recruitment/job-openings) is created for one or more job positions, with managers and a number of vacancies.
3. [Open Recruitments](/hr/functional/v2.0/recruitment/open-recruitments) lists open recruitments, each with an **Apply** button.
4. Candidates appear in [Candidates](/hr/functional/v2.0/recruitment/candidates) and move through the stages of the [pipeline](/hr/functional/v2.0/recruitment/pipeline). [Interviews](/hr/functional/v2.0/recruitment/interviews) are scheduled along the way.
5. The Candidates list has a **To employee** action, and the Onboarding module has its own pages for what follows a hire.

::: info Scope
Pages are described as an administrator sees them. Saving openings, moving candidates, scheduling interviews, sending mail and converting candidates to employees change real records and were not exercised on the demo. Which steps are automatic and which need a manual action is therefore described only where it is visible on screen.
:::
